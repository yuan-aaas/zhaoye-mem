## 2. 仓库与包职责

```text
zhaoye/
├─ package.json / pnpm-workspace.yaml / pnpm-lock.yaml   根配置，唯一锁文件
├─ tsconfig.base.json / tsconfig.arch.json / biome.json / .dependency-cruiser.cjs
├─ packages/
│  ├─ contracts/      schema、类型、错误码、预算、端口        （不依赖任何人）
│  ├─ storage/        JSON 原子写、SQLite、资产文件、presence （依赖 contracts）
│  ├─ core/           三域领域规则、CAS/幂等、查询组合        （依赖 contracts + storage 端口）
│  ├─ app/            门面、组合根、授权、生命周期            （依赖 core + contracts）
│  ├─ adapter-kit/    提示装配、回执、notice、tool-schema     （依赖 contracts）
│  └─ cli/            命令入口，只编排门面                    （依赖 app + adapter-kit + contracts）
├─ plugins/{dsh,mcp}/ 宿主映射，用户安装物                     （依赖 app + adapter-kit + contracts）
├─ tests/             根级集成与一致性测试（非 workspace 包）
├─ presets/           kernel / persona 模板
├─ scripts/           check-versions / run-tests / verify.ps1
└─ docs/              见 docs/README.md
```

| 包 | 发布名 | 目标职责 | 公开面 |
|---|---|---|---|
| `packages/contracts` | `@zhaoye/contracts` | zod schema、推导类型、错误码、预算常量、端口接口 | 全部 |
| `packages/storage` | `@zhaoye/storage` | 原子文件、数据根、人格 JSON 存储与版本、SQLite、资产文件、presence | `ensureDataRoot` / `atomicWrite` / `openIdentityStore` / `createPresence` / `openBackupDb` / `createAssetStore` |
| `packages/core` | `@zhaoye/core` | 身份服务（CAS/幂等/内核保护/投影渲染）、备份领域规则、资产校验规则 | `createIdentityService` / `createBackupService` / `createAssetService` |
| `packages/app` | `@zhaoye/app` | `AssistantService`、唯一组合根、任务账本、预算、doctor | `createZhaoye`、门面类型 |
| `packages/adapter-kit` | `@zhaoye/adapter-kit` | prompt 装配、receipt 校验、notice 渲染、项目映射、tool schema | 对应函数 |
| `packages/cli` | `@zhaoye/cli` | `bin: zhaoye`：init / doctor / identity / presence / export / migrate | `run(argv)` |
| `plugins/dsh` | `dsh-plugin-zhaoye` | 宿主生命周期、能力探测、工具注册、会话注入 | `register(ctx)` |
| `plugins/mcp` | `@zhaoye/mcp` | MCP tools / resources | `createMcpServer()` |

**硬规则**

1. `packages/*` 不单独发布；只有 `plugins/*` 是用户安装物，发布时把 `@zhaoye/*` bundle 进去。
2. 插件只 import 公开入口，不得 import 其他插件。
3. `src/internal/` 只在包内可见，跨包导入由 depcruise 拦截。
4. `app` 依赖 `contracts + core + storage`（组合根必须构造具体存储），不依赖 `adapter-kit` 或具体适配器；`core` 只依赖 `contracts`（存储端口接口在 contracts），不碰 `node:fs`；`storage` 不含领域语义。

## 3. 依赖与架构规则

现行规则（`.dependency-cruiser.cjs`，仅扫 `packages/*/src` 与 `plugins/*/src`）：

| 规则 | 约束 |
|---|---|
| `contracts-pure` | 只允许 contracts 自身与 zod；禁止 Node 内建模块 |
| `storage-no-domain` | 禁止依赖 core/app/adapter-kit/cli/plugins |
| `core-no-fs` | 禁止 `fs` / `path` / `os` / `child_process`（含 `node:` 前缀） |
| `core-no-upper` | 禁止依赖 app/adapter-kit/cli/plugins |
| `app-no-adapters` | 禁止依赖 adapter-kit/cli/plugins |
| `kit-pure` | 只依赖 contracts |
| `plugin-public-only-*` | 只允许本插件、app/adapter-kit/contracts、宿主 SDK、Node 内建 |
| `no-cross-internal-*` | 禁止跨包导入另一包的 `src/internal/` |
| `no-circular` | 禁止循环依赖 |

M1 需要同步调整的点：

- `storage` 仍然只依赖 `contracts` + Node 内建，不需要放宽规则；`core-no-fs` 保持不变，哈希、路径、SQLite 全部留在 `storage`。
- 删除 `packages/contracts/src/events.ts` 后，`packages/contracts/test/smoke.test.ts` 中的事件信封用例改为身份文档契约用例。
- 插件对 `node_modules` 目前全放开，选定真实宿主 SDK 后在 M4 收紧为白名单。

## 4. 数据根与运行形态

默认数据根 `~/.zhaoye`（Windows 按 `%USERPROFILE%` 解析），目标布局：

```text
<data-root>/
├─ manifest.json                     { format:'zhaoye-data', schema_version:1, assistant_id, created_at }
├─ identity/
│  ├─ identity.json                  权威数据（五段，见 01 §3.1）
│  ├─ identity.md                    Markdown 派生投影，可删可重建
│  ├─ versions/<12 位 revision>.json 不可变历史快照
│  ├─ versions/index.jsonl           快照元数据（含已淘汰项）
│  └─ operations.jsonl               幂等/操作回执（非事实源，有界轮转）
├─ backup/                           M2 起
│  ├─ zhaoye.db                      SQLite（WAL）
│  └─ exports/<batch_id>/            原始导出件与摘要
├─ assets/                           M3 起
│  ├─ manifest.json
│  └─ files/<asset_id>/...
└─ presence/
   ├─ owner.json                     当前活跃实例
   └─ last-released.json             最近一次离开/接管记录
```

创建与打开遵循守护式规则：空目录才允许自动 init；有数据痕迹但缺 manifest 一律 `CORRUPT_DATA`，绝不初始化成空库；旧 v3 journal 布局不迁移。完整状态表见 [04 §5.2](04-M1-契约与人格记忆开发设计.md#52-数据根打开守护表)。

运行形态：M1 只有 CLI 与测试（进程内），M4 起 DSH 插件常驻；空闲超时、handoff 属于 M4，不在 M1。

### M1 契约与人格记忆

- 目标：能建根、能打开、能读写人格、能回滚、能诊断；所有写入经过唯一门面；重开一致。
- 包含：`contracts` 重建（删事件信封、补身份/查询/错误契约）、`storage` 的原子文件与数据根与人格存储与 presence、`core` 身份服务、`app` 最小门面与组合根、`cli` 的 `init/doctor/identity/presence`、失败注入与跨进程测试。
- 不做：SQLite、导入、检索、资产、模型调用、认知蒸馏、向量检索。
- DoD：见 [04 §10](04-M1-契约与人格记忆开发设计.md#10-退出条件与验收命令)。
- 详细设计：[04-M1 契约与人格记忆开发设计](04-M1-契约与人格记忆开发设计.md)。

### M2 备份库与检索

- 目标：把外部记忆系统的只读导出变成可查询、可验证、可恢复的本地副本。
- 包含：SQLite schema 与迁移、批次/记录/版本表、WAL 安全备份、只读 `SourcePort` 与首个导出格式、幂等导入、FTS5 全文检索、范围过滤与证据元数据。
- DoD：完整/部分/失败批次语义正确；重复导入幂等；越权查询被拒；冷数据可回退召回；空结果与损坏可区分；备份恢复核验通过。
- 需先决：SQLite 驱动选型（`node:sqlite` 实验特性 vs `better-sqlite3` 原生编译）在 M1 末拍板，见 [docs/README §5](README.md#5-当前待拍板)。

### M3 资产库与完整门面

- 目标：资产可发现、可校验、可导出，但检索不等于执行。
- 包含：manifest schema、目录扫描与路径约束、SHA-256 复核、只读读取端口、跨域任务步骤与局部失败可诊断。
- DoD：越界路径拒绝；摘要不符拒绝；跨域局部失败可重试且不假报成功；适配器只经门面。

### M4 首个宿主接入

- 包含：`plugins/dsh/src/host.ts` 单点适配宿主 API、工具面（identity/记忆/presence/doctor）、会话开始注入（≤2800 码点固定预算）、能力探测、presence handoff 与空闲超时、conformance 全绿。
- DoD：十项真机验收逐条签收；未过项写明限制与替代路径；宿主升级后工具面变化能被 conformance 捕获。

适配器能力矩阵（M4 定稿基线）：

| 能力 | DSH | MCP | CLI |
|---|---|---|---|
| 工具注册 | ✅ | ✅ | ✅ |
| 提示注入 | ✅ 全量 | instructions 文本 | 每轮传入 |

新插件必须通过的 8 条 conformance（缺一不算落地）：

| # | 断言 | 验证方式 |
|---|---|---|
| 1 | 只 import 公开入口，不碰 `src/` | depcruise |
| 2 | 工具 schema 与 contracts 生成结果一致 | 快照比对 |
| 3 | 错误带 `action` 透传，不吞异常 | 注入假错误 |

## 6. 工程约束

1. **验证入口**：优先 `pnpm verify`；受限沙箱中 `pnpm -r` 可能 `spawn EPERM`，改用 `pwsh ./scripts/verify.ps1`（按依赖拓扑直接调用本地 `tsc`/`node`，不经 pnpm 转发）。
2. **测试执行**：`scripts/run-tests.mjs` 逐个 `import()` 编译产物，不 spawn 子进程；编译产物缺失时以非零退出并报告路径，不把“没发现测试”当成功。
3. **跨进程用例**：由 PowerShell 两次调用 `node`，不用 `child_process` 管道。
4. **Windows 文件语义**：`fs.rename` 对文件是替换语义，对目录不保证；因此用“临时文件 + rename”而不用目录级切换；目录 fsync 在 Windows 不可用，只能尽力而为，文档与测试要写明这一限制。
5. **中文路径**：至少一条 fixtures 用例使用含中文的数据根。
6. **版本**：根 `package.json` 的 `version` 是唯一来源，8 个包清单同值，由 `check-versions.mjs` 断言。
7. **lint 范围**：Biome 排除 `docs/` 与生成物；文档不参与格式化。
8. **可执行边界**：依赖规则只扫生产源码，测试目录不参与；新增包必须同时补 `tsconfig.arch.json` 与 depcruise 规则。

## 7. 每个切片的交付要求

一次填充一个可运行切片，并同时提交：

1. 所属包的实现与公开 API 更新。
2. 正常、边界、失败、重试用例；涉及文件或跨进程时补对应故障测试。
3. 架构验证：无越层依赖、无跨包 internal 导入、写路径唯一。
4. 里程碑 DoD 的勾选结果与未解决限制。
5. 契约或架构决定变化时，先更新 03/01 或新增 ADR，再改代码。

不以“入口存在”“包能编译”作为业务完成的依据。
