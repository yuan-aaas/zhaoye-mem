# 07 记忆工具本地存储与通用备份调研

> 2026-11-25 · 调研记录。覆盖支持本地持久化的代表性工具，包括同时提供云服务的产品。当前开发以 DSH Mneme 为主，多格式接入留待后续实现。

照夜可以沿用现有 SQLite 备份库，按来源、批次、记录、版本和授权范围管理备份。各工具的原件、索引和字段语义不同，识别格式、采集快照、字段映射和回填由对应适配器处理。会话检索由宿主授权的原生记忆工具提供。 [备份库设计](05-M2-备份库与检索开发设计.md) · [会话查询与备份回填设计](06-M2.1-记忆工具查询与备份回填设计.md)

## 1. 当前优先级

- **以 DSH Mneme 为首个实现和验收目标。** 沿用已有的只读采集、授权查询、备份核验和独立 SQLite 导出，继续验证空 Mneme 实例加载后可搜索、可读详情，以及归档和权限过滤是否符合预期。DSH 会话内的工具调用按 M4 的真机计划验收。 [Mneme 实测与里程碑](02-工程与里程碑.md#m2-备份库与检索) · [M2.1 回填设计](06-M2.1-记忆工具查询与备份回填设计.md)
- 后续扩展时，以 Mneme 的往返结果作为回归基线。新增工具的支持范围以各自的真实样本和目标实例验收为准。

## 2. 本地存储格式

### SQLite 主存储

- **DSH Mneme**。主库为 SQLite `memory.db`，Markdown 是按类型组织的可编辑镜像。`memories` 中的部分文档记录只包含摘要和路径。备份以一致性快照和授权范围内的记录为基础，文档正文按需单独授权采集。 [Mneme 官方文档](https://github.com/slow-stack/mneme/blob/main/dsh-mneme/README.md)
- **memU**。支持本地 SQLite 和 PostgreSQL。SQLite 分表保存资源、记忆条目、分类和分类关联，向量以 JSON 文本保存。可共用 SQLite 快照机制，字段、用户归属和关系需要专门转换。 [memU SQLite 文档](https://github.com/NevaMind-AI/memU/blob/main/docs/sqlite.md)

### Markdown 原件

- **OpenClaw**。内置记忆使用工作区 `MEMORY.md` 和 `memory/YYYY-MM-DD*.md`，默认 SQLite 用于检索。备份保留长记忆、每日笔记和相对路径。LanceDB 插件有独立存储，需按插件接口接入。 [OpenClaw 记忆文档](https://docs.openclaw.ai/concepts/memory) · [LanceDB 插件文档](https://docs.openclaw.ai/plugins/memory-lancedb)
- **Claude Code Auto Memory**。项目记忆默认位于 `~/.claude/projects/<project>/memory/`，包含 `MEMORY.md` 索引和主题文件，可配置目录。备份需保留项目归属、相对路径和索引引用。 [Claude Code 记忆文档](https://code.claude.com/docs/en/memory)
- **Hermes Agent**。`memories/MEMORY.md` 和 `memories/USER.md` 持久化整理后的记忆，`state.db` 保存会话历史并提供 FTS5 检索。备份时保留两类 Markdown 的原有角色，会话历史使用单独的采集范围。 [Hermes 持久记忆文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)
- **Basic Memory**。Markdown 原件包含笔记的元数据、观察和关系，SQLite 用于本地索引。优先采集文件树及固定链接，目标实例可从文件重建索引。 [Basic Memory 技术架构](https://docs.basicmemory.com/reference/technical-information) · [笔记格式](https://docs.basicmemory.com/concepts/knowledge-format)

### JSONL、向量库和图数据库

- **MCP 官方 Memory Server**。`memory.jsonl` 保存实体和关系，观察内容属于实体。往返时要保留实体标识、观察和关系端点。 [MCP Memory Server 官方实现](https://github.com/modelcontextprotocol/servers/tree/main/src/memory)
- **Mem0 开源版**。Python 版支持本地 Qdrant，记忆条目由配置的向量库持久化，SQLite `history.db` 保存变更历史。条目优先通过已配置的本地实例按范围读取，有历史保留要求时同时采集历史库。 [Mem0 开源版说明](https://github.com/mem0ai/mem0/blob/main/docs/open-source/overview.mdx) · [Python 接口](https://github.com/mem0ai/mem0/blob/main/skills/mem0/client/python.md)
- **Graphiti**。支持本地 Neo4j 和 FalkorDB，持久化实体、关系和原始事件，事实包含有效时间和来源。采集和恢复需保留关系端点、时间范围和事件引用。 [Graphiti 官方仓库](https://github.com/getzep/graphiti)

## 3. 后续实现方向

1. **按产品和格式版本注册适配器。** 把版本识别、只读采集、字段转换和目标导出从 Mneme 应用入口中提取出来。共用 SQLite 快照、Markdown 目录遍历和 JSONL 解析机制。适配器各自解释字段、权限和记录标识，通用库负责批次、授权和版本管理。
2. **保留原件并支持交换。** 保存经过授权的原始快照或目录，以及映射后的记录和原件引用。跨工具交换可使用版本化的 `manifest.json` 和 `records.jsonl`。导出时声明目标格式能保留哪些字段，并列出无法表达的关系、附件、历史版本或权限范围。
3. **按代表性格式扩展。** Mneme 闭环稳定后，优先用 OpenClaw 内置 Markdown 和 MCP Memory Server JSONL 验证文件目录和图谱文件，再用 memU 验证不同 SQLite schema 能共用采集与入库流程。备份来源和恢复目标可以分别接入。
4. **通过目标工具回读验收。** 在空实例上完成加载、搜索和详情比对，核对条数、内容、来源和权限。存在关联或归档时增加对应检查，同时核验原件摘要。
