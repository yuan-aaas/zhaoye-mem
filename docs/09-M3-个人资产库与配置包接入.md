# 个人资产库与 AI Config Bundle 接入

`ai-config-bundle` 自带清单、目录和 CLI，可独立维护和迁移。照夜把整个项目登记为一项 `config` 资产。外层清单管理定位、文件摘要和读取入口，原项目负责自己的内容和维护方式。

## 配置包里有什么

- `01-skills/` 保存技能说明及其配套脚本和资料，通常以 `SKILL.md` 为入口。
- `02-rules/` 保存规则，`04-commands/` 保存命令模板，`05-snippets/` 保存可复用片段。
- `03-memory/` 保存经验和知识文档，`07-knowledge/` 保存知识资料。这些文件在照夜里仍按资产查找和读取。
- `06-work/` 保存工作归档，`07-knowledge/daily/` 保存个人日记。两者都在照夜助手的本地读取范围内，延续原项目的 Git 忽略规则。原件随配置包迁移。
- 原生 `manifest.json` 声明包名、版本、模块及本机链接状态。`_cli/bundle.py` 提供原项目的查看、搜索和维护命令，`_meta/` 保存迁移说明等元数据。照夜解析原生清单并扫描包内文件。

## 空库和迁移目录

初始化一个新照夜数据根会创建空资产库。已有数据根可以用 `zhaoye assets init` 补建。

```text
<照夜数据根>/
├─ manifest.json             # 照夜数据根标记
├─ identity/                 # 人格原件和版本
├─ backup/
│  ├─ zhaoye.db              # 初始化好的空 SQLite 备份库
│  └─ exports/               # 首次导入前为空
├─ presence/                 # 宿主运行锁
└─ assets/
   ├─ manifest.json          # 照夜资产登记清单
   └─ files/                 # 空库中为空目录
```

空库的 `assets/manifest.json` 内容如下。

```json
{"schema_version":1,"assets":[]}
```

已有配置包时，把它的项目根整体放入 `assets/files/ai-config-bundle/`。资产 ID 对应该层目录名。登记前至少需要如下文件。原生清单中声明的可索引模块目录须存在，目录可以为空。

```text
assets/files/ai-config-bundle/
└─ manifest.json              # 配置包自己的清单
```

只有一个空技能模块时，可以用以下原生清单，再创建同一层的空目录 `01-skills/`。完全没有模块时可以设为 `"modules": {}`。

```json
{
  "name": "AI Config Bundle",
  "version": "1.0.0",
  "description": "个人 AI 配置",
  "modules": { "01-skills": { "path": "01-skills/" } }
}
```

登记核对原生清单中已声明的模块，再扫描项目内的普通文件。工作归档、个人日记、原生清单及配套文件可按需查找和读取。`.git` 元数据、符号链接和目录联接不进入资产读取范围。通过项目自身方式维护后，可重新登记同一 ID 同步外层清单。迁移时关闭正在写入的宿主，复制整个照夜数据根，在新环境配置 DSH 的 `dataRoot`，再核验。

## 接口

- **管理端** `zhaoye assets init` 初始化空库。`zhaoye assets register-config-bundle <asset_id>` 登记已经放好的目录或更新登记信息。写入只涉及照夜清单，由照夜实例持有数据根时执行。
- **CLI 只读** `zhaoye assets list` 查资产，`zhaoye assets files <asset_id>` 查文件。两者支持 `--query`、`--limit`、`--offset`。查询词按空白拆分，每个词都要命中资产 ID、名称、描述或指定资产的文件路径。它们使用清单查询。
- **CLI 读取和校验** `zhaoye assets read <asset_id> <path>` 返回经 SHA-256 和字节数校验的 UTF-8 正文与文件元数据，单文件上限 128 KiB。`zhaoye assets verify <asset_id>` 核对所有已登记文件。各命令都支持 `--data-root` 和 `--json`。
- **应用层** `createZhaoye(...).assets` 提供登记、读取、核验和配置包写入接口。`openAssetLibrary(dataRoot)` 提供 `list`、`files`、`read`、`readBytes`、`verify`，可在持有数据根的实例运行期间使用。
- **DSH 查找和读取** `zhaoye_asset_find` 可按路径或「8月日报」一类的词匹配。`zhaoye_asset_read` 分页读取 UTF-8 正文，`zhaoye_asset_read_bytes` 分段读取大文件或其他格式的原件，返回 Base64。续读使用上页的 `sha256` 和 `next_offset`。
- **DSH 维护配置包** `zhaoye_asset_write` 通过配置包的 `_cli/bundle.py` 执行 `create`、`update`、`delete`、`archive` 并同步外层清单。创建使用原项目的模板，工作报告通过 `archive` 新增。更新与删除需要目标文件当前的 SHA-256。写入由 DSH 请求本次用户确认。Windows DSH 自带 Python 时可直接使用，其他安装在可信 profile 中指定 `assetBundlePython` 的绝对路径。`zhaoye_asset_refresh` 用于项目外部发生变更后的主动同步。

文件内容作为资料返回。运行原件脚本与修改指定资产文件使用独立的权限路径。字段规范见 [记忆核心技术设计](03-记忆核心技术设计.md#34-资产-manifestschema_version-1)。
