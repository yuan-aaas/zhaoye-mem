## 4. 维护规则

1. **状态头必须可验证**：写「实测日期 + 证据命令」，不写“应该可以”。例如 `2026-10-30 · scripts/verify.ps1 退出码 0 · 12 条测试通过`。
2. **单一事实源**：里程碑只在 02 记一次，阶段设计引用 02 的编号，不复制目标与 DoD 全文。
3. **阶段收尾三件事**：04 的结论回写 02（勾选 + 偏差说明）；新暴露的契约变更回写 03；准备下一阶段时新开 `05-<阶段>-开发设计.md`，04 保留不改（作为历史记录）。
4. **文档不写代码能自证的东西**：字段长度上限、接口签名以 `packages/contracts` 与代码为准，文档只解释“为什么这样定”和“怎么验”。
5. **归档只读**：被取代的文档移入 `归档/` 并加一行失效说明，不原地改写成“半新半旧”。
