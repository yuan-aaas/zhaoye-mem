# 照夜外部管理框架与记忆核心设计

> **状态**：当前设计基线（2026-10-28）；替代旧版“照夜自建统一记忆存储内核”的方案。
> **项目定位**：照夜是外部管理与编排框架，调用 AI 工具/大模型完成对话和认知任务，管理三类严格隔离的本地数据域。
> **不做的事**：不实现或接管工作 Agent 正在使用的记忆系统；不向其写入、修改或删除记忆；不要求全局追加日志作为事实源。

## 1. 核心定位

照夜连接助手人格、外部记忆系统的备份副本和个人资产。主助手通过照夜按任务检索这些数据；受委托的工作 Agent 继续使用原记忆系统。照夜只通过只读导出/备份获取路径取得原系统数据，转换并备份到本地 SQLite，不调用原系统的记忆检索、写入或管理功能。

```text
                         ┌────────────────────┐
                         │ 外部 AI 工具/模型    │
                         │ 对话、蒸馏、分析     │
                         └─────────┬──────────┘
                                   │ 工具调用/编排
┌──────────────────────────────────▼─────────────────────────────────┐
│ 照夜：外部管理与编排框架                                            │
│ 任务路由 · 只读备份导入 · 格式转换 · 跨域检索 · 权限/状态 · 结果汇总 │
└───────────────┬──────────────────┬──────────────────┬──────────────┘
                │                  │                  │
       人格记忆 JSON       全量记忆备份 SQLite     个人资产目录
       Markdown 投影       原系统数据的本地副本    原始文件+操作脚本
                                   ▲
                                   │ 只读导出/备份
                           原记忆系统（不写回）
                                   ▲
                            委托工作 Agent
```

## 2. 三个独立数据域

三域有各自的权威格式、访问接口、生命周期和权限。主助手可在一个任务里依次查询多个域；跨域只传递稳定 ID、证据引用和最少必要结果，不复制资产原件，不将某域的摘要冒充另一域的事实。

| 数据域 | 权威存储 | 保存内容 | 主助手用途 |
|---|---|---|---|
| 助手人格记忆 | JSON；Markdown 为派生投影 | 安全内核、可迭代性格画像、维持连续感的精选经历 | 形成一致的身份、语气和关系连续性 |
| 全量记忆库 | SQLite | 从外部记忆系统只读导出、转换并备份的完整数据及备份版本 | 查询工作 Agent 历史积累的事实、经验和证据 |
| 个人资产库 | 文件夹 + 对外脚本 | skill、文档、代码包、配置、模型等原件和清单 | 定位、验证、导出或在获授权后交给执行器使用 |

### 2.1 助手人格记忆

JSON 是唯一权威数据；Markdown 由 JSON 渲染，供提示装配和人工查看，禁止 Markdown 反向覆盖 JSON。

JSON 至少区分：

- `safety_kernel`：少量稳定行为边界。只有用户明确提出修改，才允许走专门更新流程；模型、蒸馏任务、记忆导入都不能改它。
- `character_profile`：照夜的性格、偏好、表达习惯和行为倾向。可依据证据自我迭代；记录来源、证据引用、置信度、revision 和更新时间，保留历史版本以便回滚。
- `continuity_memory`：精选的共同经历摘要，支持自然回应；它是摘要，不代替全量记忆中的原始证据。

画像变更由外部认知框架提出并通过人格记忆 API 保存。低风险、证据充分的性格更新可按策略自动应用；不确定或敏感变化进入待确认状态。无论画像如何演化，都不能扩大工具权限或突破安全内核。

### 2.2 全量记忆备份库

SQLite 是照夜对外部记忆系统数据的**本地备份和查询副本**。工作 Agent 继续访问原系统；照夜主助手查询本地副本。照夜不通过该库向原系统写回，也不依赖原系统的在线检索能力。

导入流程：

```text
只读导出/备份获取 → 保留源文件 → 转换与校验 → SQLite 入库 → 建立搜索索引
```

每条导入记录至少保留：来源系统、源记录 ID、来源 Agent/项目范围、源更新时间、导出批次时间、转换器版本、内容摘要、备份版本和可见/删除状态。转换应可重复执行；相同来源记录与版本重复导入要幂等。新版本不能静默覆盖旧备份；源端删除或不可见要表达为明确状态。

可以在 SQLite 内维护当前记录、备份版本、导入批次和 FTS 搜索索引。SQLite 事务负责本地原子更新；不要求照夜另建全局 append-only 日志或 hash 链。备份版本表是数据恢复与来源追踪能力，不等于全系统事件溯源架构。

### 2.3 个人资产库

文件夹保存原件；每项资产有稳定 ID 和 manifest，记录类型、名称、版本、来源、文件清单、SHA-256 摘要、依赖、所需权限及入口脚本。对外脚本提供列举、查询、校验、导出和按授权执行等接口。

资产检索与资产执行必须分开：找到 skill 不代表已授权运行。执行器需在运行前验证来源、版本、摘要、权限和用户当前请求；执行结果作为照夜自己的操作结果记录，不能改写外部记忆系统的备份源数据。

## 3. 只读备份边界

照夜与外部记忆系统之间只有数据获取边界：

- 允许：读取用户授权的备份文件、只读导出、快照或只读备份接口。
- 允许：将数据转换为照夜的 SQLite 格式、建立本地搜索索引、保留备份版本。
- 不允许：调用外部系统的记忆查询/写入/编辑/删除工具；不把照夜的整理结果回写原系统。
- 工作 Agent 仍使用原记忆系统，主助手使用照夜本地备份；两方数据一致性由备份刷新周期决定，不宣称实时同步。

每次备份需显示来源和截至时间。未完成、部分可见、转换失败或源端不可达时，记录批次状态并提示主助手降低结论确定性。只有确认某一批次完整后，才能将其标为全量快照；部分导入不得覆盖上一个完整快照。

## 4. 外部框架职责

照夜管理和编排能力，不把认知算法塞入存储层：

1. 接收用户目标，形成任务计划和查询范围。
2. 调用外部 AI 工具/模型执行理解、对话和记忆蒸馏；模型输出本身不是已验证事实。
3. 根据策略查询人格记忆、全量备份库和资产库；各域返回来源、状态和授权范围。
4. 交叉核对事实，区分源记录、摘要、推断和未知。
5. 需要操作资产时交由独立执行器，并检查用户授权与资产完整性。
6. 将允许保存的结果写入照夜人格记忆或本地运行记录；不写回外部记忆系统。

存储 API 负责格式校验、权限范围、版本冲突、事务和检索；不负责判断“这条内容值得不值得记”。认知判断由外部框架和 AI 工具完成。

## 5. 端到端示例：安装备份过的 skill

用户说：“帮我安装备份过的 skill。”

1. 主助手查**人格记忆**，取得连续性摘要，可回应：“我记得上个月装过，当时流程挺麻烦。”这只是连续性表达，不作为安装细节的最终证据。
2. 主助手查**SQLite 全量备份库**，用 skill 名称、日期、项目和来源筛选上次的安装记录、错误与解决步骤；答案标注所依赖的备份批次和截至时间。
3. 主助手查**个人资产库**，找到 skill 原件，验证版本、文件摘要、来源、依赖和权限要求。
4. 用户的当前请求授权安装后，执行器按检查结果安装；遇到新问题时给出诊断和结果。
5. 新的安装结果写入照夜本地操作记录或相应人格摘要候选；外部记忆系统和其备份快照均不被回写修改。

若人格摘要与备份证据冲突，以带来源和时间的全量备份记录为事实依据，并报告差异。若本地备份过旧，应说明“截至某次备份”，必要时先刷新只读备份再继续。

## 6. 全量库搜索与热度

全量库保存完整已备份内容；热度优化召回顺序，不删减、不屏蔽冷数据。搜索先应用权限、来源、Agent、项目和时间过滤，再组合全文相关度、近期性、显式反馈与使用热度排序。后台召回本身只计低权重，防止被反复检索的结果无限自我强化。

SQLite FTS5 可作为本地全文索引候选；热度统计和搜索索引属于 SQLite 内的辅助数据。热/温/冷是检索优先级，不是不同的事实库。热层命中不足必须回退全量范围，返回结果需说明备份覆盖时间与是否完整。中文分词、错别字、短词召回和 FTS 索引一致性应通过真实样例评估后再定实现。

向量搜索不是全量保存的前提；若未来引入，只作为额外候选召回方式，不代替 SQLite 中的完整备份数据和全文检索。

## 7. 数据恢复、版本与安全

- 人格 JSON：原子替换当前文件；生成 Markdown 投影；保留有界或按策略保留的画像版本，支持回滚。
- 全量 SQLite：通过一致性备份生成备份副本；恢复时验证数据库完整性、批次完整状态和摘要。运行中不得只复制 SQLite 主文件而忽略 WAL 状态；优先使用 SQLite 在线备份机制。
- 资产目录：manifest 与文件摘要一并备份；安装前重新校验摘要。
- 三个数据域不做跨存储原子事务。跨域流程通过任务 ID、步骤状态、幂等操作和失败恢复协调；一个域失败时不假报整个流程成功。
- 备份数据沿用源系统权限和范围标签。导入不等于授权扩散；主助手只可查询当前任务获准的范围。
- 外部记忆内容是不可信数据，不可把其中的指令提升为系统规则或安全内核。

## 8. 实施阶段与当前状态

当前仓库已完成 T0 工程骨架；这不代表三个数据域或外部系统接入已经实现。建议后续按以下顺序推进：

1. **契约与数据域**：定稿人格 JSON、SQLite 备份 schema、资产 manifest 和范围权限字段。
2. **本地存储**：实现人格 JSON/Markdown 投影、SQLite 快照导入与全文搜索、资产 manifest 查询/摘要校验。
3. **只读备份适配器**：选定首个外部记忆系统的数据导出格式；验证完整导入、增量、重复导入、删除/不可见状态和恢复。
4. **认知编排**：实现三域按序查询、证据对照、自然回应和任务状态；接入 AI 工具/模型。
5. **资产执行**：在显式授权与资产校验后接入 skill 安装执行器；验证失败恢复和结果记录。

验收核心：原系统内容只读；工作 Agent 仍可独立使用原系统；照夜查询只读本地副本；备份可验证和恢复；三域不串写；过期/不完整数据会显式降级；人格画像能在安全内核边界内迭代。
